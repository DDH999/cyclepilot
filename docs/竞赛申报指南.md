# 竞赛申报指南（挑战杯 / 国创赛）

> 本文档说明：这套系统拿去参赛需要**补什么**、**怎么定位**、**怎么写**。
> 具体赛制以当届官方通知为准，本文只讲判断标准与材料结构。

## 一、先做一个战略判断

### 1.1 现状的真实分数

| 维度 | 现状 | 评委会怎么看 |
|---|---|---|
| **方法论严谨性** | ⭐⭐⭐⭐⭐ 有泄漏审计、FDR、PBO、DSR、22 项引擎测试 | 强项 |
| **工程完成度** | ⭐⭐⭐⭐ 全流程一键跑，33 秒，46+ 图表 | 强项 |
| **可复现性** | ⭐⭐⭐⭐ 有 requirements、缓存、脚本化 | 强项 |
| **实证结论的价值** | ⭐⭐⭐ 负结果（公开 alpha 全灭、量价无 alpha） | 双刃剑 |
| **策略收益** | ⭐ **Sharpe 0.22 / DSR 0.18** | **明显短板** |
| **应用落地** | ⭐⭐ 只有研究功能，无实盘/实盘验证 | 短板 |

### 1.2 两个定位，必须选一个

**定位 A：「我们找到了一个赚钱的量化策略」** ← 不建议

- 现实是 Sharpe 0.22，DSR 0.18，一被追问就露馅
- 评委里只要有一个懂行的，问一句"你做过 PBO 吗"就结束了
- 即使现在去调参凑出一个好看的数字，也过不了"样本外"这一问

**定位 B：「我们建了一个能量化 A 股量化研究可信度的框架，并用它证伪了若干流行结论」** ← 建议

理由：

1. **负结果在学术上是合法的结论**。挑战杯明确看重"科学性"，一篇能严谨否定流行做法的作品，比一篇吹牛的更容易过学术审查。
2. **我们有罕见的材料**：五次自我推翻的完整记录（含一次数据管道 bug 伪造 alpha 的完整还原）。这是"科学精神"最硬的证据，多数参赛作品拿不出来。
3. **工程量大**：24 个模块、2,066 只标的、47 个季度、36 个因子、478 个公开 alpha 实测、53 张图表。工作量是可量化的。

> 一句话包装：**"我们不是做了一个能赚钱的策略，我们是做了一个能让你知道你的策略是不是在骗你的系统。"**

## 四、材料清单与结构

### 4.1 挑战杯（学术科技作品）

| 材料 | 页数建议 | 核心内容 |
|---|---|---|
| 作品申报书 | 按官方模板 | 选题背景、创新点、技术路线、成果 |
| **研究报告 / 论文** | 25~40 页 | 直接以 `docs/研究设计与方法.md` 为骨架扩写 |
| 附件：代码与数据说明 | 5~10 页 | 复现步骤、数据来源与合规声明 |
| 答辩 PPT | 15~20 页 | 见下 |

论文建议结构：

```
1 引言（问题、动机、贡献）
2 相关工作（幸存者偏差、数据窥探、过拟合检验）
3 方法（四层框架）        ← 用 docs/研究设计与方法.md §4
4 数据与清洗              ← §3
5 实验设计与结果          ← §6（重跑后填）
6 案例研究：一次被数据管道伪造出的 alpha   ← 最独特，建议单独成章
7 局限与讨论
8 结论
附录：复现指南、代码结构
```

### 4.2 国创赛（大学生创新创业训练计划）

国创赛周期长（1~2 年），重视**项目可行性与过程管理**，材料更偏"项目"而非"论文"：

| 阶段 | 材料 | 重点 |
|---|---|---|
| 立项申报 | 申报书、创新性说明 | 讲清"要解决什么问题"，不要一上来讲技术 |
| 中期检查 | 进展报告、阶段成果 | 强调已完成的工程与已获得的结论 |
| 结题验收 | 结题报告、成果附件 | 论文/软著/开源仓库/用户反馈 |

**国创赛特别提示**：评审多为非金融背景教师，**技术细节要降维解释**。建议准备一页"给外行看的一页纸"：

> 我们用一句话说：**市面上的股票回测大多会"骗人"，我们做了一个能检测出"哪里在骗人"的工具，并用它检查了 500 多个公开的选股公式，发现绝大多数已经失效。**

### 4.3 答辩 PPT 结构（15~20 页）

| 页 | 内容 | 时间 |
|---|---|---|
| 1 | 一句话问题：为什么你的回测不可信 | 30s |
| 2-3 | 四类偏差是什么（各配一张图） | 2min |
| 4 | 我们的框架（四层图） | 1.5min |
| 5 | 引擎规则完备性（T+1/涨跌停/税费表） | 1min |
| 6 | 单元测试 22/22（截图） | 1min |
| 7-8 | 控制实验：随机切分 vs Purged WF 的 AUC 对比图 | 2min |
| 9 | FDR 前后对比图（36 因子 → 少数通过） | 1.5min |
| 10 | PBO / DSR 图 | 1.5min |
| 11 | **案例：被数据管道伪造出的 alpha** | 3min |
| 12 | 结论：负结果的学术价值 | 1.5min |
| 13 | 局限与下一步 | 1min |
| 14 | 演示（30 秒跑完 + 控制台） | 2min |

## 五、现场演示脚本（必须提前练）

```powershell
# 第 1 步：证明引擎规则（2 秒）
python tests/test_backtest.py
#   → 通过 22 / 22

# 第 2 步：跑完整流程（33 秒）
python backend/run_all.py
#   → 完成 4/4

# 第 3 步：打开控制台展示门禁判定
python backend/app.py
#   → 门禁页面显示"拒绝部署：未通过门禁"
```

**演示的关键话术**：

> "请注意这一页写的是**拒绝部署**。这个系统最核心的功能不是告诉你买什么，而是告诉你**什么时候不该信自己**。"

这句话通常能让评委记住。

## 六、常见失分点（逐条自查）

| 失分点 | 自查 |
|---|---|
| 只讲收益不讲风险 | 我们的主角是 PBO/DSR，不是收益率 ✅ |
| 无法现场复现 | 有 33 秒全流程 + 缓存 ✅ |
| 使用未来函数 | 有泄漏审计 + 时点对齐 ✅ |
| 数据来源不可靠 | 全部标明来源与获取方式 ✅ |
| 过度宣称 | 有专门的局限性章节 ✅ |
| 与已有工作雷同 | 需补对比表（P1 第 5 项）⚠ |
| 演示翻车 | 需演练（P0 第 4 项）⚠ |
| 讲不清商业价值 | 国创赛需补"谁会用"（教师、学生、量化入门者）⚠ |
