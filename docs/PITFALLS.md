## 1. 前复权在长历史上会产生负价

### 现象

```
AAPL 1984-09-07  close = -10.755
00700 2004-06-16 close = -41.373
```

一只股票的价格怎么会是负的？

### 原因

前复权 = 用「今天的标准」重新折算历史价格。折算方式是**减去累计分红**。

当一只股票上市几十年、分红总额超过早期股价时，早期价格就会被减成负数。

### 后果

`pct_change()` 遇到负数会算出完全错误的收益率。**整个回测报废。**

### 解法

**存储不复权价 + 每日涨跌幅（pct_chg），复权在读取时计算。**

```
复权收盘 = 首日收盘 × cumprod(1 + pct_chg/100)
```

涨跌幅天然不受拆股、分红影响，永远不会产生负数。

**另一个好处**：增量落盘时，追加新数据不会改变已有行。如果按「块」计算复权锚点，不同块的锚点不同，接缝处会出现价格跳变。

## 2. 空仓看起来像低波动

### 现象

一个 10 只股票的 A 股组合，回测出来：

```
年化波动 1.3%
最大回撤 -2.76%
夏普    2.35
```

看起来完美。**实际是假的。**

### 原因

数据里混着「1992 年起」和「2023 年起」的股票。回测引擎用**日期并集**建网格，早期几乎没人可买 → 组合长期空仓 → 净值接近直线。

**陡峭的曲线不一定是好策略，也可能是没持仓。**

### 后果

会误判为「风控有效」「策略稳健」，进而投入真金白银。

### 解法

**计算逐日「投资率」= 持仓市值 / 净值。**

```
投资率 < 50% → 结果不可信，自动标记
```

同时做**面板覆盖对齐**：只用「共同覆盖窗口内数据完整」的股票。

## 3. 进度标记跑在落盘之前

### 现象

批量灌数据，跑了几轮都显示"进度 1080 天"，但库里实际只有 860 天的数据。

### 原因

```python
for i, d in enumerate(dates, 1):
    buf[code].append(df)               # 只进内存
    st["dates_done"].append(d)         # ← 每天标记完成
    if i % 20 == 0:
        save_status(st)                # ← 每 20 天落一次进度
    # 但 buffer 每 300 天才写库
```

**进度跑在数据前面。** 进程一崩，那 300 天里已标记的日期再也不会重抓。

### 后果

数据永久缺失，且**看起来是完好的**（进度文件显示完成）。

### 解法

**进度必须跟着数据走，不能跟着循环走。**

```python
pending.append(d)
if i % FLUSH_EVERY == 0:
    flush(buf)                    # 先落盘
    st["dates_done"] += pending   # 再标记
    save_status(st)
```

**并且**：从实际数据重建进度，而不是信任进度文件。

## 4. 用当前成分股回溯历史

### 现象

用「今天的沪深300成分股」跑 2019–2024 回测，年化 48%。

### 原因

今天的成分股 = **已经活到今天、且表现好到能进指数**的股票。

用它们回测 2019 年 = 提前知道了谁会赢。这叫**幸存者偏差**。

### 实测影响

| 票池 | 2019–2021 等权年化 |
|---|---|
| 当前成分股（58 只） | **+46.19%** |
| 全市场时点票池 | **+11.32%** |
| 差距 | **34.87pp** |

### 解法

**时点票池**：某交易日 T 的可交易全集，只用 T 及之前的信息。

```
ipo_date <= T          已上市
T - ipo_date >= 60     非次新（60 个交易日）
out_date is null or > T  未退市
```

⚠ **禁止**用「当前是否存续」筛历史——那会把已退市股的整段历史删掉。

## 5. 基准选错

### 现象

策略年化 16%，感觉不错。

### 原因

比的是**沪深300价格指数**（不含分红），而且策略买的是全市场。**两个完全不同的东西。**

### 实测影响

| 基准 | 策略超额 |
|---|---|
| 沪深300 | **+0.33pp** |
| 同池等权 | **−16.63pp** |

**同一个策略，换个基准，从「略胜」变成「惨败」。**

### 解法

**基准必须满足两条**：
1. **同池**（同样的股票池）
2. **同样持有**（等权买入持有，不是指数）

因为你的策略做的是「从池子里挑」，对照就应该是「不挑，全买」。

## 6. 限流被误判为无权限

### 现象

Tushare 明明有权限，代码却说「无权限（积分不足）」，然后永久跳过这个数据源。

### 原因

```python
except Exception as ex:
    if "权限" in str(ex):
        _PERM[name] = False        # ← 永久缓存为不可用
```

但 Tushare 对**频繁调用**返回的错误信息里也带「权限」二字：

```
抱歉，您访问接口(daily)频率超限(1次/分钟)
```

**「限流」被当成了「没权限」。**

### 后果

一个完全可用的数据源在整个进程生命周期内被禁用。

### 解法

严格区分三类错误：

```python
if "没有接口" in msg:          # 真无权限 → 永久缓存
elif "频率" in msg or "超限":   # 限流 → 不缓存，稍后重试
else:                          # 其他 → 不缓存
```

## 附加：几个自动化测试救过的坑

| 坑 | 测试怎么发现的 |
|---|---|
| 反转因子与动量因子选了**完全相同**的股票 | 发现两个因子收益数字一模一样 |
| 冲击成本系数写成 `*10`（少了一个量级） | 对照成本量级 |
| 年化成本被当成日成本扣（500 倍） | 成本占收益比例异常 |
| 不可行的 `max_weight` 被 `except` 吞掉 | 静默回退到默认值 |
| 成交价被放到错误的日子 | 断言「成交价必须是次日开盘」失败 |

**结论：测试不是为了证明代码对，是为了在它错的时候抓住它。**
